# 默认原生低延迟视频

## 当前行为

- WebCodecs 是唯一默认视频路径，入口 `DEFAULT_PLAYER = 'webcodecs'`。旧 `mse` 链接同样由原生适配器接管；旧实验偏好为 false 或没有保存偏好都不会选择 MSE
- 音画设置仅显示实际播放器状态，移除实验开关和播放器切换按钮
- 保留原 MsePlayer 的控制外壳、设置存储、触控几何和菜单，替换视频层为原生解码画布；不运行其 MP4 remux、MediaSource 或 MSE 解码流程
- 浏览器不支持、配置不支持或解码失败时，明确停止并清理音频、屏幕租约和解码资源；不自动回退 MSE、不循环重载、不创建第二路视频
- `LegacyAccessUnitAdapter` 使用已审计旧 JAR 的完整 MediaCodec 缓冲边界，支持 High/CABAC 多切片，详见 `LEGACY-VIDEO-CONTRACT.md`
- 解码提交深度保持有界；短时突发按顺序等待原生出队/出帧，压缩输入同时受帧数、字节数和等待时间限制，超限才丢弃整条依赖链并请求刷新。没有固定增加播放缓冲。保留单张待绘帧。连续恢复失败仍受次数及超时限制；持续真实绘制后刷新连续失败预算，累计诊断计数不清零。接收字节、收到关键帧或长时间停顿后的单帧均不能单独恢复预算
- 参数、鉴权、按设备画质与音频偏好、保帧恢复、常亮、屏幕租约沿用既有实现

- 温连接从半个 GOP 接入时，合法但缺少参数的图像被丢弃并触发原通道关键帧请求；不再当作格式损坏立即停止。已有配置但缺少首个关键帧也主动请求恢复。启动/恢复等待上限与正常帧播放排队分开
- 失败提示按固定类别显示首帧超时、关键帧超时、连续恢复失败、原生解码错误等，不显示原始异常或设备信息

## 验证

`webcodecs-core.test.cjs` 验证 High 缓冲、参数变化、异步配置、背压、资源释放及恢复预算。预算测试先在旧实现复现第三次恢复错误终止，再验证稳定绘制可续用、连续失败仍停止

`webcodecs-lifecycle.test.cjs` 在真实 Linux WebKit 使用本地合成 H264/PCM 和隔离服务，覆盖无偏好/旧关闭偏好、新默认 URL、单张 High 图像、持续 High/Baseline、旋转和触控、设置重载、声音恢复、鉴权终止和屏幕租约。新增真实 High 八帧突发和从 delta 开始的温连接恢复用例；失败用例确认不创建 MSE converter 或第二路连接

```sh
node --test --test-concurrency=1 common/server/test/*.test.cjs
```

依赖使用现有测试环境，`NODE_PATH` 指向既有 Playwright、会话依赖和引擎依赖，`PLAYWRIGHT_BROWSERS_PATH` 指向现有浏览器缓存。其他机器通过 `WC_WEBKIT_EXECUTABLE` 指定 WebKit；测试不读取真实手机音画

## 发布与验收边界

本次只有静态前端运行文件变化，不需要重启服务；已打开文档在用户下次刷新后载入新版本。发布须核对源码与运行 HTTP 资源的 SHA256，并保留本地提交回退点

用户已反馈原 High 修复在 iPhone 切换 WebCodecs 后明显更流畅、操作更跟手。这是实机主观反馈；Linux WebKit 合成延迟不是实体 iPhone 端到端延迟，也未证明与原生 scrcpy 同条件性能相等
