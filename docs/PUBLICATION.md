# 发布准备与未决项

当前目录来自已撤回失败实验后的稳定源码快照，作为新的公开源码记录准备。旧私有仓库、Git 对象、现场交接、日志和部署状态不随附；线上服务没有被本次整理修改。

## 已整理

- 去掉 node_modules，保留两个已有 package-lock。
- 原作者 LICENSE 保持不变，补 NOTICE、第三方许可入口和修改说明。
- 不附私有发布报告、凭据、设备数据库、会话或个人 Git 元数据。
- 登录表单不再预填个人账号；测试浏览器路径改由环境变量提供。
- README 使用新绘制示意横幅，明确区分生产使用经验与开源目录的可运行性。

## 暂未随附

| 路径 / 内容 | 原因 | 恢复运行需要 |
| --- | --- | --- |
| common/engine/index.js、public/ | 压缩引擎、解码 WASM 和内嵌依赖的来源/完整通知待补 | 找到准确上游版本、重建映射及所有通知 |
| vendor 视频 scrcpy-server.jar | 派生版本内嵌 WebSocket/日志库通知待核 | 核对该版本组件及构建来源 |
| common/tools 的 ADB ZIP | 压缩包仅有 adb，可执行文件组件许可不完整 | 使用可信、适配架构、许可完整的制品 |
| 平台图片与 favicon | 未取得独立素材来源记录 | 核验授权或替换为可确认原创图标 |
| 私有发布文档、node_modules、Git 历史 | 公开用途不需要现场细节或本机依赖副本 | 不应恢复进公开提交 |

因此当前目录可用于审阅和源码记录，**尚不具备直接安装、直接投屏或发布正式安装包的条件**。不要通过添加旧 ZIP 或整个私有 .git 来“补齐”。

## 正式发行前必须完成

1. 补齐上表各制品来源与许可，确认没有混入撤回的实验代码。
2. 提供完整依赖安装、登录/TURN配置生成和受保护反向代理的通用配方。
3. 修改并验证打包流程，确保根 LICENSE 与所有第三方通知进入最终 payload。原脚本只拷贝部分目录，不能假定自动满足。
4. 在干净环境构建、解包检查，并做 iPhone/安卓实机的连接、音频、后台与中转验证。
5. 再检查最终 Git 暂存区和拟上传附件，不上传审查私有目录。需要保留历史时，另行审查历史范围和提交身份。
